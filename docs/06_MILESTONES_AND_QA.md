# Milestones and QA

## v0.010 — VERA vertical slice

Acceptance criteria:

- boots from PRG in the official emulator;
- one 40×30-tile visible region using VERA tile layers;
- animated hardware-sprite hero with keyboard and joystick movement;
- collision, one door/exit, and one inspectable object;
- regional encounter accumulator and at least three encounter types;
- dedicated combat screen with enemy art;
- individual Protocol Dice shown and totaled;
- Attack, one noncombat Skill, Item, Guard, and Flee;
- return to exploration with persistent HP and encounter state;
- one save slot that survives restart;
- deterministic developer seed and on-screen debug overlay;
- memory/VRAM allocation report generated by the build.

## Test layers

- **Host rules tests:** thousands of seeded dice rolls; valid bounds; blank-face rule; deterministic replay.
- **Converter tests:** malformed input, budget overflow, stable IDs, checksums.
- **Emulator smoke test:** boot, title, input, map, encounter, combat, save/load.
- **Regression scripts:** fixed input/seed produces expected state checksums.
- **Hardware test:** cold boot, controller, SD I/O, video boundaries, audio, long session.
- **Playtest:** comprehension, pacing, encounter variety, combat duration, navigation, text size.

## Definition of done

A feature is done only when its data format is documented, failure behavior is defined, memory budget is known, emulator smoke test passes, and user-visible behavior has been playtested or explicitly marked untested.
